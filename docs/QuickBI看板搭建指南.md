# Quick BI 看板搭建指南

> 目标：用阿里云 Quick BI 给你数仓项目的 ADS 层做可视化看板
> 成本：**0.1 元**（个人版）
> 时间：约 40 分钟

---

## 为什么用 Quick BI（而不是本地工具）

| 原因 | 说明 |
|---|---|
| **不用装本地程序** | 云端运行，绕开本机那个"权限检查"问题（Metabase 就是卡在这里） |
| **真 BI 工具** | 阿里云 Quick BI，国内企业广泛使用，简历上认得 |
| **和 DataWorks 同生态** | 你简历上已有 DataWorks，**两个连起来是完整的"数据平台"故事** |
| **便宜** | 个人版 0.1 元 |

---

## 第 1 步：开通（5 分钟）

1. 浏览器打开 **[Quick BI 购买页](https://common-buy.aliyun.com/subscription?productUnitCode=quickbi_ai_public_cn&subscriptionCode=quickbi_ai_public_cn_smart_subscription)**
2. 选择 **通用用户购买** → **个人版**
3. 点 **立即购买**（0.1 元）
4. 完成后进入 **[Quick BI 工作台](https://bi.aliyun.com/console.htm)**

> ⚠️ **前提**：你的阿里云账号需要完成**实名认证**。
> 你在天池下载过数据、开通过 DataWorks，**大概率已经认证过了**。
> 如果提示未认证，去 [账号实名认证](https://account.console.aliyun.com/v2/#/authc/home) 做个人认证（需身份证，几分钟）。

## 第 2 步：上传数据（10 分钟）

CSV 文件我已经导出好了，在这里：

```
D:\dsh\数仓实习\02-岗位与投递\项目代码\bi_exports\
├── 01_每日核心指标.csv        9 行   （日期 / PV / UV / 购买用户数 / 转化率）
├── 02_次日留存率.csv          9 行   （日期 / 活跃用户数 / 次日回访数 / 留存率）
├── 03_商品浏览Top10.csv      90 行   （日期 / 排名 / 商品ID / 浏览量）
└── 04_连续活跃天数分布.csv      4 行   （最长连续天数 / 用户数）
```

**操作**：
1. 在工作台左侧找 **数据源**（或「数据」→「数据源」）
2. 点 **新建数据源** → 选择 **本地文件** / **上传文件**
3. 把上面 4 个 CSV **逐个上传**（每个文件会成为一张表）
4. 上传时注意：
   - 第一行是**表头**（勾选"首行为列名"）
   - 日期列识别成**日期类型**（不是文本）

> 💡 如果个人版找不到"上传本地文件"入口，可以改用 **百度 Sugar BI**（[cloud.baidu.com/product/sugar.html](https://cloud.baidu.com/product/sugar.html)），
> 它也支持上传 Excel/CSV，有免费额度。

## 第 3 步：做 4 张图（20 分钟）

在工作台点 **新建** → **仪表板**（或「分析」→「仪表板」），然后加图表：

### 图 1：每日 PV / UV 趋势（折线图）

| 设置项 | 值 |
|---|---|
| 数据集 | `01_每日核心指标` |
| 图表类型 | **折线图** |
| X 轴（维度） | 日期 |
| Y 轴（度量） | PV、UV（两个都放上去） |

**看出什么**：流量走势，有没有异常波动。

### 图 2：购买转化率趋势（折线图）

| 设置项 | 值 |
|---|---|
| 数据集 | `01_每日核心指标` |
| 图表类型 | **折线图** |
| X 轴 | 日期 |
| Y 轴 | 购买转化率_百分比 |

**看出什么**：转化健康度，是否稳定。

### 图 3：次日留存率（柱状图）

| 设置项 | 值 |
|---|---|
| 数据集 | `02_次日留存率` |
| 图表类型 | **柱状图** |
| X 轴 | 日期 |
| Y 轴 | 次日留存率_百分比 |

**看出什么**：用户黏性。注意**最后一天没有次日数据**，值是 0，别当成"留存暴跌"。

### 图 4：商品浏览 Top10（条形图）

| 设置项 | 值 |
|---|---|
| 数据集 | `03_商品浏览Top10` |
| 图表类型 | **条形图** |
| 筛选器 | 日期 = 2017-11-25（先固定一天） |
| Y 轴（维度） | 商品ID |
| X 轴（度量） | 浏览量 |
| 排序 | 按浏览量降序 |

**看出什么**：热点商品集中度。

### 可选：图 5 · 连续活跃天数分布

| 设置项 | 值 |
|---|---|
| 数据集 | `04_连续活跃天数分布` |
| 图表类型 | 柱状图 |
| X 轴 | 最长连续活跃天数 |
| Y 轴 | 用户数 |

**看出什么**：用户活跃深度分布 —— **大部分用户只活跃 1-2 天，少数核心用户连续 7-9 天**。

## 面试怎么讲（重点）

做完后，你可以这样说：

> "我在数仓项目上接了一层 BI：用**阿里云 Quick BI** 基于 ADS 层做了核心指标看板，
> 包括每日 PV/UV 趋势、购买转化率、次日留存率、商品 Top10 和用户活跃深度分布。
>
> **关键是 BI 只连 ADS 层，不连明细层。**
> 因为 ADS 是预聚合好的报表层，口径统一；
> 如果 BI 直接查明细自己算，多个图表可能算出不同的数。
> 这是我理解的 BI 和数仓的分工：**数仓负责算得对，BI 负责展示得清。**
>
> 我项目里正好有《指标口径说明》，里面定义了每个指标的口径边界，
> BI 侧就按这个口径来配，避免同一个指标在不同图里数字不一致。"

**这段话的价值**：它不只说"我会用 BI 工具"，而是说出了 **BI 与数仓的边界和口径治理**——
这正是面试官想听的（说明你懂架构，不只是会拖控件）。
